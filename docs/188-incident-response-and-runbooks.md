# 188 — Incident Response & Runbooks

## Objective
Create repeatable responses to production failures.

## Incident Process
```text
Detect
 ↓
Triage
 ↓
Mitigate
 ↓
Communicate
 ↓
Recover
 ↓
Postmortem
```

## Runbooks
Create runbooks for:
- API outage
- database failure
- Redis outage
- queue backlog
- payment provider outage
- map provider outage
- notification outage
- security incident

## Postmortem
Record:
- impact
- timeline
- root/contributing causes
- mitigation
- corrective actions

Focus on system improvement rather than blame.

## Definition of Done
Critical incidents have documented response procedures and owners.
